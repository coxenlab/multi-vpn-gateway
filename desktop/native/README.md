# macOS 原生界面

SwiftUI + AppKit，最低 macOS 14。Rust core 作为本应用持有的本地子进程；管理界面初始化不启动 VM，业务沿用 core 的 HTTP 合同。Web 版保留，只有厂商登录界面使用局部 WKWebView。

当前为开发入口，尚未替换 Tauri 分发壳，未打包或安装。

正式模式的启动代码已接入 `Contents/Resources`：本地 core、runtime 工具/助手、静态登录页面、内置容器镜像与 VM 镜像均先做可读性/执行权限检查。缺件时显示具体组件，在检查通过前不创建数据、不启动 core；另一个相同 bundle ID 的应用正在运行时拒绝启动。该检查不能替代资源来源校验或完整签名验证。

正式版沿用 `~/Library/Application Support/com.vpnmgr.desktop` 和 `vpnmgr` profile；子进程只使用随包运行工具与系统 PATH，清除开发环境留下的端口、密钥、Docker context 和 profile 覆盖，运行参数由既有 `infra.json` 提供。只有首次连接运行环境时才在后台预置 VM 缓存；复制失败不会留下截断目标，并发时保留已有缓存。这里的正式模式已编译验证，尚未实际组装或运行正式 App。

## 隔离开发

从本 clone 运行 `desktop/native/dev.sh`。默认独立 `vpnmgr-native-dev` profile、`~/Library/Application Support/vpnmgr-native-dev` 数据与 `vpnmgr_native_dev_vpnnet` 网络；可用 `VPNMGR_NATIVE_DATA_DIR` 指定另一份开发数据。脚本不打包、不安装。启动界面只读配置；用户点连接/创建才会启动该开发 VM。调试二进制缺少显式开发身份会拒绝启动；核心同一数据目录的重复原生进程在生成或改写运行参数前被拒绝。

关闭窗口仅隐藏，隐藏后停止界面轮询与登录视图；退出关闭本应用持有的 stdin 管道，core 执行已有完整清理。父进程异常退出同样使管道 EOF；core 收到 SIGTERM 也清理。stdout 只消费结构化 ready 事件中的本机端口，迟到的旧进程事件不能覆盖新实例。核心退出时立即清除过期列表与进行中状态，取消旧连接；重新连接后，旧请求不能覆盖新数据、取消新操作或误报成功。未保存备注保留在本次界面会话中。

保存与后台刷新重叠时，等待旧请求结束后再取一次最新状态；多个等待者共享后续刷新，避免保存成功但新通道迟迟不出现。

维护页读取只接受当前页面、当前服务连接的最新结果；离页后不继续发起跟随读取，暂停监控/事件刷新也会丢弃在途结果。手动刷新可读取一次暂停中的列表。菜单提供 ⌘N 新建通道、⌘R 刷新当前页面和 ⌘, 打开设置；弹窗/文件面板开启时不新开创建或切换设置。真实菜单与键盘焦点仍需实窗验收。

## 已接入的功能

- 通道列表、详情、创建向导、连接信息编辑、显式启停、待应用/停用待确认/恢复、分流开关与删除确认。
- 动态适配器输入、版本选择、文本配置文件选择、BYO 安装包上传；安装包限制 1 GiB，通过受限临时文件分块上传，完成或失败后清理；密码不用于 UI 日志。
- 登录窗口、键入到容器、观看者租约回收；备注在同一 SQLite 事务中核对原文并保存。冲突时显示最新内容、保留草稿；保存期间的新输入和切换通道后的草稿都保留在本次会话中。
- 规则搜索、增删、启停、批量操作、备注与锁定、跨通道域名/IPv4/IPv6 交叠提示；显示已保存/待同步、原因和上次确认时间，支持显式连接并同步或重试。规则仍经 core 的同一校验与生效确认，HTTP 成功但 `ok:false` 的维护操作不能显示成功。
- 当前连接、上传/下载速率、搜索与 CSV 导出；页面隐藏后不发起新轮询。
- 运行环境连接、环境检查、诊断、镜像下载进度、下载源管理、配置备份导入/导出、Clash 片段、自愈开关、系统代理/TUN 状态与切换、运行事件筛选/详情/记录开关/日期导出、容器状态/残留清理/入口修复/日志、助手安装/卸载确认、菜单栏和退出。
- 镜像模板支持选择/拖入 Docker save tar/tar.gz，离线校验摘要、标签和本机架构；确认后流式加载，按实际镜像 ID 读回，重复确认不重复导入。预览有效期 30 分钟；可取消，进程退出自动回收匿名暂存文件。校验只证明包内一致性，模板来源与是否含个人数据仍由提供者保证。
- 升级数据通过目录选择准备受限副本，检查结果与副本位置可直接查看；实例核对和切换验收完成前始终保留 pending，不能自动启用。
- 开发模式禁用宿主系统代理/TUN 操作。替换其他应用设置的自动代理须由界面明确确认。

## 验证范围与剩余工作

`./verify.sh` 在 macOS 增加 Swift 无警告编译；Rust、Python、JS 检查继续沿用原入口。Swift 合同测试使用隔离 core 的实际 API 输出，执行时设置 `VPNMGR_NATIVE_FIXTURE_DIR`（含 native-channels.json/native-adapters.json/native-system.json/native-image-import.json/native-events.json/native-containers.json）。未提供夹具时明确跳过，不伪称实机 API 验收。测试还在不显示窗口的 NSHostingView 中做布局，快照不能替代真实窗口/焦点/辅助功能验收。

`LayoutTests` 生成九种内容的深浅色截图；视图缓存在当前系统下会漏画部分原生导航/系统控件，因此仅用来检查已捕获内容和布局是否崩溃，不能作为完整视觉验收通过的依据。

原生平台还需真实窗口、菜单/快捷键、深浅色、登录/上传、真实代理与 TUN 的交互验收。升级副本的目录选择/准备/结果查看已接入，正式数据启用与回退仍待运行验收。正式资源打包、签名/公证、旧数据切换和回退、企业 VPN/睡眠换网/长稳验收均未完成；发布仍被这些门槛阻挡。不要用此开发入口覆盖当前日常 App。
